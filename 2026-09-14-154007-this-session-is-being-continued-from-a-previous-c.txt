❯ why does the analytics_category_correciton says : Data is publicly accessible 
   via API as this is a Security definer view. Learn more.                      
  ⎿  ⧉ Selected 142 lines from supabase_schema.sql in Visual Studio Code

  Searched for 1 pattern, read 1 file (ctrl+o to expand)

● The problem: PostgreSQL views run as SECURITY DEFINER by default — they
  execute with the view creator's (superuser) privileges, bypassing RLS. So even
   the anon key can query this view and see all users' data.

  The fix: Add WITH (security_invoker = true) so the view respects the caller's
  RLS policies.

  Run this in your Supabase SQL Editor to replace the view:

  drop view if exists analytics_category_corrections;

  create or replace view analytics_category_corrections
  with (security_invoker = true)
  as
  select
    merchant_normalized,
    (change->>'from') as category_from,
    (change->>'to')   as category_to,
    count(*)          as correction_count,
    max(ale.created_at) as last_seen_at
  from ai_learning_events ale,
       jsonb_array_elements(changes) as change
  where change->>'field' = 'category_id'
    and merchant_normalized is not null
  group by merchant_normalized, category_from, category_to
  order by correction_count desc;
